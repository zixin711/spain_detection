## 2. 分级体系（按用户定义）

### 2.1 五级判据表

| 等级 | 名称 | 肉眼特征 | 紫光(395nm)响应 | 物理深度 | 本质 |
|---|---|---|---|---|---|
| **L1** 🟢 | 微轻度（隐形/早期萌发） | 无明显变色，或极微弱隐约灰斑，肉眼极难察觉 | 点状/微弱黄绿荧光 | ≤ 0.1 mm，无损结构 | 肉眼不可见的隐形孢子期 |
| **L2** 🔵 | 轻度（点状/表面着色） | 孤立小黑点、浅灰斑点，总面积 < 5% | 清晰局域亮荧光，与无霉区边界明显 | 0.1 ~ 0.5 mm | 局部表层点状发霉期 |
| **L3** 🟡 | 中度（块状/缝隙侵入） | 缝隙明显变黑，连片斑块，面积 5% ~ 30% | 连续条带状/块状强荧光 | 0.5 ~ 2.0 mm，擦拭有阻力 | 深达缝隙的连片成熟期 |
| **L4** 🔴 | 重度（片状/厚质结块） | 大面积漆黑或深褐，面积 > 30%，立体厚层 | 大面积高亮荧光，信号饱和 | > 2.0 mm，伴起泡/粉化 | 高密度高厚度重灾期 |
| **L5** 🟣 | 严重（结构破坏/墙皮剥落） | 严重发黑脱落，空鼓、开裂、剥落、石膏松软 | 基底与剥落边缘杂乱深度荧光，几何异常 | 基材结构性损坏 | 墙体结构损坏级，**停止机械研磨** |

### 2.2 三证据通道

| 分量 | 权重 | 含义 | 来源模态 |
|---|---|---|---|
| **H** | 0.40 | 紫外响应分：异常区覆盖率 × 相对墙面照明场的平均衰减深度（**不是黄绿荧光强度**，见 3.5） | **紫外图** |
| **M** | 0.35 | 覆盖分：霉变区面积 ÷ 有效墙面面积，按暗度/致密度加权 | 白光图（紫外图可用荧光覆盖代理，口径不同） |
| **L** | 0.25 | 深度厚度分：阴影梯度、高光缺失、起泡粉化等代理量或实测 | **白光图**（紫外图几乎无此线索） |

> 若流程图中 H/M/L 原意是"高/中/低三档密度霉斑的面积占比"，只需改 `configs/grading.yaml` 的通道定义，框架不变（开放问题 #1）。

## 3. 光源模态自适应（v0.3 核心改动）

训练与检测的输入**不保证成对**，可能只有白光图，也可能只有紫外图。因此系统按"先判光源、再选专家、最后按可用证据分级"三步处理。

### 3.1 光源自动判别

`app/modality.py` → 输出 `modality ∈ {white, uv, unknown}` + 置信度。

**特征（紫外图与白光图的域差极大，非常好分）**

| 特征 | 白光图 | 395nm 紫外图 |
|---|---|---|
| 亮度均值/中位数 | 中高 | 明显偏低 |
| 主色相分布 | 分散，含大量近灰轴像素 | 高度集中于蓝紫（OpenCV H ≈ 120~150） |
| 通道关系 | R≈G≈B 的灰像素占比高 | B 通道显著大于 R，B−R 均值为正且大 |
| 色彩熵 | 高 | 低 |
| 高饱和小面积亮斑 | 少 | 荧光点/斑，且色相偏黄绿（H ≈ 35~95） |

**实现**：先用上述统计量做逻辑回归（可解释、零训练成本、几十张样本即可标定阈值）；
数据量上来后换 MobileNetV3-Small（输入 128×128，二分类），预期准确率 > 99%。
两者都保留，`unknown`（置信度 < 0.8）时前端弹一次确认："这张是白光照还是紫光照？"，
用户选择后写回样本库，作为判别器的增量训练数据。

### 3.2 双专家模型 + 路由

不做"一个模型吃两种光源"，因为两个域的**类别语义本身就不同**：白光下的黑/绿/白/粉表型在紫外下不可见，
紫外下的荧光形态在白光下不存在。强行合并会互相拖累。

**白光专家 `seg_white`**（YOLO11-seg，9 类）

| id | 类别 | 说明 |
|---|---|---|
| 0-3 | `mold_black` / `mold_green` / `mold_white` / `mold_pink` | 表型主类 |
| 4 | `grout_mold` | 缝隙霉（填缝剂发黑），L3 关键判据 |
| 5 | `substrate_damage` | 空鼓/开裂/剥落/起泡/粉化/石膏松软，**L5 关键判据** |
| 6-8 | `damp_stain` / `efflorescence` / `dirt_stain` | 负类：水渍返潮、返碱盐析、污渍其他 |

**紫外专家 `seg_uv`**（YOLO11-seg，6 类，按荧光形态而非表型分类）

| id | 类别 | 说明 | 对应等级证据 |
|---|---|---|---|
| 0 | `fluor_point` | 点状/微弱黄绿荧光 | L1 |
| 1 | `fluor_local` | 清晰局域亮荧光，边界明显 | L2 |
| 2 | `fluor_band` | 连续条带状/块状强荧光 | L3 |
| 3 | `fluor_saturated` | 大面积高亮饱和荧光 | L4 |
| 4 | `fluor_chaotic` | 剥落边缘杂乱深度荧光、几何异常 | L5 |
| 5 | `fluor_artifact` | **荧光干扰负类** | 见下 |

> ⚠️ **`fluor_artifact` 是紫外模态最重要的负类。** 395nm 下会发荧光的不只有霉菌：
> 洗衣粉/清洁剂残留中的荧光增白剂、部分乳胶漆与腻子的荧光助剂、白色塑料件与硅胶密封胶、
> 纸张、某些矿物盐析、宠物尿渍。不建这个负类，紫外模态的误报率会高得没法用。

**备选方案**（数据量不足时）：共享 backbone + 域特定 BN + 双检测头的单模型。省标注、省显存，
但工程复杂度和调试成本都高，暂列为备选，见开放问题 #2。

### 3.3 证据可用性矩阵与等级能力

| 输入模态 | H 荧光 | M 覆盖 | L 深度 | 可判等级范围 | 权重重归一化 | 置信度系数 |
|---|---|---|---|---|---|---|
| **仅白光** | ✗ | ✓ | ✓ | **L2 ~ L5**；L1 不可判 | M 0.583 / L 0.417 | ×1.0 |
| **仅紫外** | ✓ | △ 荧光覆盖代理 | ✗ | **L1 ~ L4**；L5 仅"疑似" | H 0.53 / M 0.47 | ×0.85 |
| **双模态** | ✓ | ✓ | ✓ | **L1 ~ L5** 全量 | 0.40 / 0.35 / 0.25 原式 | ×1.0 |

结果里始终输出 `level`（最可能等级）、`level_range: [min, max]`（该模态能确定的区间）
与 `needs_confirmation`（是否建议补另一光源的照片）：

- 仅白光且未见任何霉斑 → `L0_UNVERIFIED`，提示"无法排除 L1 隐形萌发期，建议补一张 395nm 紫光照"
- 仅紫外且检出 `fluor_chaotic` → `L5?`（疑似结构破坏），提示"请补一张白光照确认是否有空鼓剥落"
- 仅紫外时 L4 与 L5 无法可靠区分，统一给 `L4+`，`level_range = [L4, L5]`

### 3.4 面积口径的模态差异（重要）

L2/L3/L4 的 5% / 30% 阈值是**按白光可见霉斑面积**定义的。
紫外下的荧光区面积通常**大于**白光可见面积（包含尚未显色的早期活跃区），直接套用会系统性高估等级。

因此：

- `configs/grading.yaml` 中维护**两套面积阈值**：`area_thresholds.white` 与 `area_thresholds.uv`
- 两套阈值的对应关系由一小批**配对样本**标定：拟合 `A_uv ≈ k · A_white + b`，
  实测 k 预计在 1.2~2.0 之间，由数据说话
- **注意**：训练与日常检测不需要配对数据，但**阈值标定阶段需要**（预计 150~300 对即可）。
  这是本设计里唯一还需要成对拍摄的环节。

### 3.5 紫外响应量化（v0.4 按真实样张重写）

**关键修正：395nm 下墙面霉菌通常不发黄绿荧光，而是比墙面更暗。**

对用户提供的 5 组 L1~L5 配对样张实测：

| 指标 | 实测结果 |
|---|---|
| 黄绿荧光像素占比（H∈[35°,95°], S>0.25, V>0.2） | **0.0000**（五张紫外图全部为 0） |
| 蓝紫色相像素占比 | 1.000 |
| 霉斑区相对局部背景的亮度偏离 | 负值，且随等级加深：L1 −1.9 → L5 −7.2 |

物理解释：室内墙面涂料普遍含荧光增白剂，在 395nm 激发下整面墙发出蓝白荧光；
霉菌菌丝与孢子吸收紫外并淬灭这层荧光，因此**霉斑呈现为暗区**；
菌落生长前沿的菌丝层则散射出亮白色蕾丝状细丝，是非常有辨识度的特征。

**算法：照明场归一化后的绝对衰减**

1. 用灰度形态学闭运算估计"干净墙面"的照明场 `L(x,y)` —— 闭运算把周围明亮的墙面值
   填进暗的霉斑区，得到"这里如果没有霉应该有多亮"。在 256px 缩略图上算，再插值回原尺寸。
2. `R = V / L`，干净墙面 R≈1，霉斑 R<1，亮丝 R>1。
3. 菌落本体 = `R < 0.88`；菌落前沿亮丝 = `R > 1.05` 且高频纹理强；两者合并为异常区。
4. 荧光干扰（荧光增白剂残留、塑料件、纸张）= `R > 1.10` 且纹理平滑，从异常区中扣除。
5. `H = 0.65 · min(覆盖率/0.60, 1) + 0.35 · min(衰减深度/0.40, 1)`

**为什么不用相对局部背景的 z-score**：z-score 的分母（标准差）本身随霉量增长，
实测 L1 与 L5 会被归一化成几乎相同的数值，完全无法区分等级。换成绝对衰减后，
L1→L5 的覆盖率与衰减深度都严格单调（见第 6 章标定结果）。

发射型黄绿荧光作为补充通道保留 —— 部分基材上确实会出现，但不能作为主判据。

### 3.6 有效墙面区域（面积分母）

两种模态都需要墙面分割来做面积分母。方案：一个轻量墙面分割模型（`wall_seg`，可用 YOLO11n-seg 单类，
白光/紫外混合训练即可，墙面轮廓在两种光源下都靠边缘与平面结构，域差影响小），
失败时回退到"整幅画面"并在结果中标注 `wall_area_fallback: true`（此时面积占比不可靠，等级降置信）。
UI 上画出墙面轮廓，允许用户手动调整。

### 3.7 深度分 L 的获取

| 优先级 | 手段 | 适用模态 |
|---|---|---|
| 1 | 视觉厚度代理：阴影梯度、局部对比方差、高光缺失、LBP/Gabor 纹理能量 | 白光 |
| 2 | 伴生特征：检测到 `substrate_damage`（起泡/粉化/剥落）→ 直接进 >2mm 档 | 白光 |
| 3 | LiDAR / 深度图（若前端可提供） | 两者 |
| 4 | 机器人测距 / 研磨阻力 / 电流反馈 | 两者，最准 |

纯图像模式下毫米阈值（0.1 / 0.5 / 2.0 mm）**无法直接测量**，系统输出"深度档位 + 参考毫米区间"并明确标注非实测。
**紫外单模态下深度线索几乎为零**，此时 L 分量置空并按 3.3 表重归一化。

### 3.8 双图同时上传时的处理

用户一次传两张（或多张）时：按光源判别分组 → 各自跑对应专家模型 →
若两张视角接近（ORB + RANSAC 配准成功，重叠 > 60%）则做实例级融合：
掩膜映射到同一坐标系，白光实例吸收对应位置的荧光响应作为实例级 H 分；
配准失败则**不融合**，按两次独立检测输出，取更严重的一级作为整体结论，并提示"两张照片未能对齐"。

### 3.9 紫光安全提示（UI 常驻）

395nm 属 UV-A，短时使用风险低，仍需：不直视光源、不照射他人眼睛与皮肤、儿童宠物回避、
单次照射控制在数十秒内。

## 4. 分级判定逻辑

### 4.1 硬规则（自上而下，先命中先返回；括号内为所需模态）

```
[白光] 检测到 substrate_damage，或深度分 L 超阈值        → L5（halt_grinding = true）
[紫外] 检测到 fluor_chaotic 且面积显著                  → L5?（疑似，建议补白光复核）
[白光] 可见面积占比 > 30%，或厚层代理超阈值，或伴起泡粉化  → L4
[紫外] fluor_saturated 面积占比 > uv_thr_L4             → L4+（[L4, L5]）
[白光] 面积占比 5%~30%，或缝隙连续变黑（缝隙线霉 > 40%）  → L3
[紫外] fluor_band 为主，面积占比落在 uv_thr_L3 区间      → L3
[白光] 面积占比 0~5% 且孤立点斑                          → L2
[紫外] fluor_local 为主                                 → L2
[紫外] 仅 fluor_point，白光无可见霉斑或无白光图           → L1
[白光] 无可见霉斑且无紫外图                              → L0_UNVERIFIED
其他                                                    → L0（未见异常）
```

### 4.2 指数校验

按 3.3 表重归一化后计算 `I_mold`，与规则判级比对：差 ≥ 2 级则标 `conflict = true`，
取两者中**较严重**的一级 —— 宁可高估，不可漏判。
同级内用 `I_mold` 给连续严重度（如"L3，严重度 0.62，接近 L4"），让机器人能感知临界状态。

### 4.3 UNKNOWN 回退（对应流程图右分支）

- 图像质量不合格：拉普拉斯方差 < 60（模糊）、过曝或欠曝像素 > 30%
- 有效墙面占比 < 40%（遮挡、拍的不是墙）
- **光源判别置信度 < 0.8 且用户未确认**
- 模型平均置信度 < 0.35，或霉菌类与负类（水渍/返碱/荧光干扰）置信度差 < 0.10
- 面积占比落在等级边界 ±1% 且证据互相矛盾
- 多图上传时配准失败且结论互相矛盾 ≥ 2 级

→ 返回 `level: "UNKNOWN"` + 原因 + 重拍指引；机器人侧执行"原地二次扫描 / 切换光源 / 人机协助"。

## 5. 算法流水线

```
上传的 1~N 张图
  → EXIF 旋转校正 → 长边缩放 1600（GPU 富余，比 v0.2 的 1280 提高）→ 质检（模糊/曝光/遮挡）
  → 光源判别 → {white 组, uv 组}
  → 墙面分割（wall_seg）→ 有效面积分母
  → 白光组 → seg_white 推理（imgsz 1024, conf 0.25, iou 0.6, retina_masks=True）
     紫外组 → seg_uv   推理（同参数，独立权重）
  → 掩膜后处理：形态学开闭 → 小面积过滤 → 邻近实例合并 → 缝隙线判定
  → 实例特征：面积/轮廓/HSV 直方图/暗像素比/凸包填充率/LBP 纹理熵/阴影梯度
              紫外实例额外算：荧光响应强度、形态类型、基线归一化值
  → （可选）跨模态配准与实例级融合
  → 证据通道 H / M / L 按可用性裁剪并重归一化 → I_mold
  → 硬规则判级 → 指数校验 → level + level_range + needs_confirmation，或 UNKNOWN
  → 建议知识库 + 机器人执行指令（按区域下发）
  → 渲染标注图（底图可切白光/紫外）→ JSON + PNG + PDF
```

### 5.1 验收指标

| 指标 | 目标 |
|---|---|
| 白光专家 mask mAP50 | ≥ 0.60（GPU 上可用更大模型，较 v0.2 的 0.55 上调） |
| 紫外专家 mask mAP50 | ≥ 0.55 |
| 光源判别准确率 | ≥ 0.99 |
| 纯负样本假阳性率（白光：水渍/返碱/污渍；紫外：荧光增白剂/塑料件/涂料助剂） | ≤ 8% |
| 等级一致性加权 Kappa | ≥ 0.7；**低估 ≥2 级的漏判率 ≤ 2%** |
| L1 召回率（紫外或双模态下评估） | ≥ 0.6 |
| 端到端延迟（RTX 3090，单图） | ≤ 400 ms（TensorRT FP16） |

## 5.2 阈值标定结果（用真实配对样张）

`data/paired_calib/` 下有 5 组 L1~L5 的白光/紫外同机位配对样张，全部阈值以此标定。
**每级只有 1 组样本，属种子值**，补足样本后跑 `scripts/calibrate_grading.py` 重新拟合。

**实测量（照明场归一化后）**

| 真值 | 白光可见面积占比 | 白光衰减深度 | 紫外异常面积占比 | 紫外衰减深度 | 面积加权厚度分 |
|---|---|---|---|---|---|
| L1 | 0.019 | 0.156 | 0.061 | 0.179 | 0.456 |
| L2 | 0.018 | 0.207 | 0.120 | 0.182 | 0.689 |
| L3 | 0.173 | 0.189 | 0.318 | 0.204 | 0.670 |
| L4 | 0.462 | 0.314 | 0.781 | 0.238 | 0.883 |
| L5 | 0.486 | 0.400 | 0.676 | 0.338 | 0.853 |

两点值得注意：

- **白光面积占比与用户给定的 5% / 30% 阈值完全吻合**：L1/L2 都在 5% 以下，L3 落在 5~30%，
  L4/L5 都在 30% 以上。分级定义本身经得起数据检验。
- **L1 与 L2 在白光下几乎没有差别**（1.9% vs 1.8%），区分它们的是紫外覆盖率（0.061 vs 0.120）
  和白光衰减深度（0.156 vs 0.207）。这正是"L1 肉眼不可见"的直接体现。

**标定后的阈值**

| 参数 | 值 | 依据 |
|---|---|---|
| 白光 L2/L3 面积分界 | 0.05 | 用户定义，实测验证 |
| 白光 L3/L4 面积分界 | 0.30 | 用户定义，实测验证 |
| 白光 L2 下限（面积 或 衰减） | 0.03 / 0.18 | 低于此值判为"白光下不可见"，交给紫外区分 L1/L2 |
| 白光 L5 提示（面积 且 衰减） | 0.45 / 0.38 | L5 样张 0.486 / 0.400 |
| 紫外 L1/L2 分界 | 0.09 | L1 0.061，L2 0.120 |
| 紫外 L2/L3 分界 | 0.20 | L2 0.120，L3 0.318 |
| 紫外 L3/L4 分界 | 0.50 | L3 0.318，L4 0.781 |
| 紫外疑似 L5 的衰减阈值 | 0.30 | L4 0.238，L5 0.338 |
| 厚度分 L4 阈值 | 0.85（且面积 ≥ 0.20） | 代理量未标定，不能单独定级 |
| I_mold 指数区间 | L1 <0.24 / L2 <0.33 / L3 <0.50 / L4 <0.76 / L5 ≥0.76 | 三种模态下的实测值 |

**回归验证结果**（`tests/test_pipeline.py::test_calibration_samples_reproduce_levels`）

| 真值 | 白光单模态 | 紫外单模态 | 双模态 |
|---|---|---|---|
| L1 | `L0_UNVERIFIED` [L0–L1] ✓ 诚实地说判不了 | **L1** ✓ | **L1** ✓ |
| L2 | L2 ✓ | L2 ✓ | L2 ✓ |
| L3 | L3 ✓ | L3 ✓ | L3 ✓ |
| L4 | L4 [L4–L5] ✓ | L4 [L4–L5] ✓ | L4 [L4–L5] ✓ |
| L5 | L4 [L4–L5] ✓ 区间含真值 | L4 [L4–L5] ✓ | L4 [L4–L5] ✓ |

L4/L5 给区间而不给定值是对的：这两级的分界是**基材是否结构性破坏**，
样张里没有拍到明确的空鼓/剥落，系统就不该替用户下这个结论，而是提示补拍确认。

| Nature Sci. Data 无人机建筑表面缺陷数据集 | 外墙缺陷 | 大 | 开放获取 | 补充 |

### 6.2 紫外数据（必须自采，公开数据集里没有）

**好消息：v0.3 不要求配对，采集成本大幅下降。** 可以只拍紫外图并单独标注。

- 硬件：395nm UV-A 手电（机器人为板载 UV LED 阵列），关灯环境
- 场景覆盖：卫生间瓷砖缝、窗台结露处、衣柜背墙、地下室、厨房吊顶、外墙内侧
- 规模目标：每个荧光形态类 ≥ 200 张；`fluor_artifact` 负类 ≥ 300 张（清洁剂残留、
  荧光增白剂污渍、白色塑料件、硅胶密封胶、新刷乳胶漆、纸张）
- **L1 的标注方法**：L1 白光不可见，没有可靠的白光标签。做法是对已知会长霉的潮湿区域
  提前拍紫外图并定期复拍，用后期实际长出的霉**反证**当初那批荧光点确实是 L1。
  这条时间序列是 L1 标注唯一自洽的来源。
- **配对子集**：另采 150~300 组白光/紫外配对样本，**仅用于标定** 3.4 节的两套面积阈值映射，
  不参与模型训练。

### 6.3 下载与清洗

`scripts/download_datasets.py`：配置在 `configs/datasets.yaml`，Roboflow 走 SDK（需 `ROBOFLOW_API_KEY`），
Kaggle 走 `kagglehub`，落 `data/raw/<source>/` + `manifest.json`（来源/许可/时间/文件数）。

`scripts/prepare_dataset.py`：

1. 格式统一转 JPEG，长边 ≤ 2048（GPU 环境可留更高分辨率），PIL verify 剔损坏
2. pHash 跨数据集去重
3. 质量过滤：拉普拉斯方差 < 60 剔模糊；亮度越界剔除（**紫外图单独设阈值**，其正常亮度本就低）
4. **打模态标签**：用 3.1 的判别器给每张图自动标 `white` / `uv`，低置信度的进人工复核
5. 标签映射：白光数据 → 9 类；紫外数据 → 6 类（`configs/label_map.yaml` 分两套）
6. 框 → 掩膜：只有检测框的数据集用 **SAM2** 以框为 prompt 生成掩膜，按 IoU 与面积合理性过滤
7. 负样本补充
8. 按场景分组做 8:1:1 划分，防止同场景连拍跨集泄漏
9. 输出两套 YOLO-seg 数据集：`data/processed/white/` 与 `data/processed/uv/`，各自 `data.yaml`

### 6.4 增强策略

白光：HSV 抖动（色调幅度小，颜色是关键特征）、亮度对比度、运动模糊、JPEG 噪声、透视变换、
随机裁剪、mosaic（末 10 epoch 关闭）、copy-paste。
紫外：**不做色相抖动**（荧光色相本身就是判据），改为亮度/曝光抖动、紫光源距离模拟（径向亮度衰减）、
噪声（低光高 ISO 噪点）、透视变换、copy-paste。
两者均**不做上下翻转**（霉菌有重力/结露方向先验）。

## 7. 训练方案（Ubuntu + 双卡）

### 7.1 环境

- Ubuntu 22.04 / 24.04，NVIDIA 驱动 ≥ 570
- **CUDA 12.8+**。RTX PRO 5000 Blackwell 是 **sm_120**，必须用 cu128 及以上的 PyTorch 轮子
  （`pip install torch --index-url https://download.pytorch.org/whl/cu128`）；
  默认的 cu118/cu121 轮子在这张卡上会报 `no kernel image is available`。
  RTX 3090 是 sm_86，同一套 cu128 轮子兼容。
- Ultralytics 最新版，`AMP=True`，`cache='ram'`（内存够时显著提速）

### 7.2 两张卡怎么用

架构不同（sm_86 vs sm_120），**不建议 DDP 混合**——同步会被 3090 拖慢，收益有限。推荐分工：

| 卡 | 分工 |
|---|---|
| **RTX PRO 5000（48GB）** | 主训练：白光专家大模型、长时间实验、大 batch 大分辨率 |
| **RTX 3090（24GB）** | 并行跑紫外专家 / 消融实验；训练完成后常驻跑推理服务 |

需要多卡加速同一个任务时，建议同架构卡之间做 DDP；当前配置下并行跑两个实验的吞吐更高。

### 7.3 超参

| 项 | 白光专家 | 紫外专家 |
|---|---|---|
| 模型 | `yolo11l-seg.pt`（48GB 卡）；3090 上用 `yolo11m-seg` | `yolo11m-seg.pt` |
| imgsz | 1024（小目标多，比默认 640 收益明显） | 1024 |
| batch | 16（PRO 5000, imgsz 1024）/ 8（3090） | 12 |
| epochs | 300，`patience=50` | 300，`patience=50` |
| 优化器 | AdamW，`lr0=0.001`，`weight_decay=0.0005`，warmup 3 | 同 |
| 其他 | `cos_lr=True`，`close_mosaic=15`，类别不均衡时过采样负类与 `substrate_damage` | `fluor_artifact` 过采样 |

### 7.4 导出与部署产物

- `best.pt` → ONNX（opset 17，动态 batch）→ **TensorRT FP16 引擎**
- ⚠️ **TensorRT 引擎不跨 GPU 架构通用**：3090 和 PRO 5000 各自 build 一份，
  文件名带架构标记（`seg_white_sm86.engine` / `seg_white_sm120.engine`），服务启动时按实测卡自动选
- 保留 ONNX 作为兜底（换卡、CI 测试、无 TensorRT 环境时可用 ONNX Runtime-GPU）
- 分级模块单独标定：`scripts/calibrate_grading.py` 用配对子集拟合两套面积阈值与荧光基线，输出标定报告

| 等级 | 方案 | 要点 |
|---|---|---|
| **L1 微轻度** | 常规清洁 + 环境干预 | 干布/微湿布擦拭；重点是**除湿通风**（RH < 60%）而非清洁；低功率 UV 抑菌可选；无需药剂；2 周后紫光复检 |
| **L2 轻度** | 局部清理 | 中性清洁剂或 3% 过氧化氢局部擦拭 → 彻底干燥；排查局部结露源（窗框、冷水管、外墙冷桥）；1 周后复检 |
| **L3 中度** | 加强清理 | **先湿法**（禁止干刷，防孢子扬尘）→ 除霉剂静置 10~15 min → 刷洗 → 清水擦净 → 强制干燥；缝隙霉需**铲除旧填缝剂重新填缝**；戴 N95/KN95 + 手套 + 护目镜；3 天后复检 |
| **L4 重度** | 深度清理 | 隔离区域、封闭通风口；分区回字形慢速作业防交叉污染；受污染的墙纸/石膏板/保温层建议铲除更换；同步排查渗漏与保温缺陷；重涂防霉涂料；1 周 + 1 月双次复检 |
| **L5 严重** | 专业治理 | **停止一切机械研磨与擦拭**（会造成墙皮二次脱落）；标记报警 → 联系专业霉害治理机构；先做渗漏与基材含水率检测，必要时局部拆除重做防水找平；治理后验收复检 |

**按类别补充**
- `mold_black`：着色深、易渗入涂层微孔，L3 以上通常需铲涂重刷防霉涂料
- `mold_green`：多与持续高湿相关，重点在除湿与通风改造，单纯擦拭复发率高
- `mold_white`：先确认不是返碱 —— 用水湿润，溶解消失的是盐析，不溶且有绒毛感的是霉
- `mold_pink`：多在瓷砖缝、地漏周边，重点是缝隙填补与日常保干
- `grout_mold`：填缝剂多孔吸水，表面擦拭只能除色不能除菌，L3 起建议铲缝重填
- `substrate_damage`：直接进入 L5 流程，不给清洁建议
- `damp_stain`（负类）：提示"存在潮湿风险，先排查渗漏/结露，否则必长霉"
- `efflorescence`（负类）：提示为返碱，用除碱剂处理，路径与除霉不同
- `fluor_artifact`（紫外负类）：提示"该荧光疑似清洁剂残留/荧光增白剂/塑料件反应，非霉菌活性"

**通用安全提示（每次结果附带）**
- 禁止将含氯漂白剂与含氨类清洁剂混用（会产生氯胺气体）
- 清理时保持通风，佩戴口罩手套；孕妇、儿童、呼吸道敏感人群回避作业现场
- 单块霉变面积超过约 1 m²，或涉及中央空调/通风管道，建议交专业机构
- 免责声明：本系统为图像识别辅助工具，不提供菌种鉴定与健康诊断

## 11. 机器人执行指令

| 等级 | action | 关键参数 |
|---|---|---|
| L1 | `dry_wipe` | `spray=0, uv_power=low, brush_speed=slow, passes=1` |
| L2 | `micro_spray_wipe` | `spray=micro(抑菌剂), grind_speed=medium, passes=1` |
| L3 | `high_pressure_scrub` | `spray=high_pressure, brush=strong, dwell_sec=600, passes=2, grout_focus=true` |
| L4 | `deep_clean` | `pattern=回字形, speed=slow, spray=max, passes=3, isolate=true` |
| L5 | `halt_and_alert` | `grinding=false, wipe=false, mark_zone=true, alert=true, require_human=true` |
| UNKNOWN / 区间过宽 | `rescan` | `rescan_in_place=true, switch_light_source=true, adjust_light=true, fallback=human_assist` |

- 附带 `target_regions`（各区域掩膜多边形 + 各自等级），机器人按区域差异化作业，不整墙一刀切
- `level_range` 跨度 ≥ 2 级时（典型：仅紫外的 `L4+`），机器人应先**切换光源二次扫描**再决定动作，
  而不是直接按上限执行——这正好复用流程图右侧的"未知等级 → 原地二次扫描"分支

## 14. 待确认的开放问题

1. **H / M / L 的口径**：本稿定为"H 荧光活性、M 覆盖、L 深度厚度"，与你给的三类判据一一对应。
   若原意是"高/中/低三档密度霉斑的面积占比"，改 `configs/grading.yaml` 即可，框架不变。
2. **双专家 vs 单模型**：本稿采用"白光专家 + 紫外专家 + 光源路由"。
   若希望只维护一个模型，可改为共享 backbone + 域特定 BN 的单模型（省标注、工程更复杂）。要哪种？
3. **紫外硬件**：395nm 光源型号与功率？机器人是否板载 UV LED？
   目前的紫外阈值基于你给的 5 组样张，换光源/换机型后需要重新标定。
   另外要确认：这 5 组样张是同一支手电、同一台手机拍的吗？如果不是，阈值的普适性还要再验证。
4. **深度测量**：纯图像只能给档位加参考区间，且紫外单模态下几乎没有深度线索。
   是否有测距 / LiDAR / 研磨阻力反馈可接入？
5. **配对标定子集**：已经用你给的 5 组样张（每级 1 组）完成首轮标定，全部等级都能复现。
   但每级 1 组的统计意义很弱，**建议每级再补 20~30 组**，尤其是：
   - L1 的更多样本（最难，也最有价值）
   - 不同墙面材质（乳胶漆 / 瓷砖 / 壁纸 / 水泥）——涂料的荧光增白剂含量差别很大，
     直接影响"墙面基线亮度"，是当前算法最大的不确定性
   - 明确带空鼓剥落的 L5 样本（现在的 L5 样张只是覆盖极广，没有结构破坏的直接影像证据）
6. **面积的分母**：5% / 30% 是占整幅画面还是占有效墙面区域？本稿按后者设计。
7. **机器人协议**：第 11 章 `robot_action` 字段是否要改成你们真实机器人的指令格式？
8. **数据授权**：CC BY 4.0 数据集需在产品中署名出处，能否接受？有无商用限制？
9. **多用户与云端**：当前为单机单用户 + 本地历史。若需要多用户/云端同步，存储与鉴权要另行设计。
